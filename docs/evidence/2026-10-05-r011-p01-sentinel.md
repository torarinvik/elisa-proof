# R-011 P-01 workload sentinel (2026-10-05)

The P-01 fixture contract is stored separately from runner implementation in
`scripts/p01_sentinels.json` (`elisa-proof-p01-sentinels-v1`). Each of the six
current fixtures has a repository-relative path, byte size, SHA-256 digest and
expected CLI outcome. Positive cases require `proved`/exit 0; refusal cases
require `failed`/exit 1; the bounded adversarial quantifier case must remain
unproved and exit 1. The runner validates the exact fixture set and each path
and content identity before it invokes the proof binary. It reports expected
outcomes from the manifest alongside measured fixture identities.

Focused verification:

```text
$ python3 scripts/test_p01_baseline.py
P-01 baseline: fixed identities, scenario labels and replay completeness enforced
exit status: 0
```

No `build/elisa-proof` executable is present in this checkout, and no proof
product was built for this change. Consequently this evidence validates the
runner contract only; it is not a fresh semantic rerun or a performance
measurement. This sentinel covers the existing P-01 set and does not yet add
field equality, composed calls, resource-heavy inputs or adversarial fact
growth. The paired benchmark, scaling curves and seven alternating post-warmup
rounds required for comparative claims remain open.
